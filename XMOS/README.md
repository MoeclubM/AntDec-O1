# XMOS XU316 音频板

器件为 XU316-1024-QF60B-C24，600 MHz，两个核组，每组 512 KiB RAM；启动存储为 W25Q16JV 2 MiB。依赖 XMOS XTC 15.3.1、lib_xua 5.2.0、lib_xud 4.0.0、lib_dsp 6.3.0。

## 音频与音效

USB 高速 UAC2 的发送接口包含 32-bit PCM、24-bit PCM（4 字节子槽）和 32-bit RAW 原生 DSD 三个档位。PCM 速率覆盖 44.1 / 48 / 88.2 / 96 / 176.4 / 192 / 352.8 / 384 / 705.6 / 768 kHz。原生 DSD512 使用 705.6 kHz 的 32-bit 字传输，即每声道 22.5792 Mbit/s；DoP256 使用 705.6 kHz PCM 载波。全速 UAC1 当前使用 24-bit PCM，最高 96 kHz。

USB 软件音量已禁用，音量由控制板设置 DAC，防止主机音量运算破坏 DoP 标记或原生 DSD。音频管线在 DoP 第一个候选标记就保持原样，等待 lib_xua 完成锁定。原生 DSD 与 DoP 不经过均衡器。

均衡器使用双硬件线程分别计算左右声道的 10 段二阶滤波器，支持 Peak、Low shelf、High shelf、Low pass、High pass，以及六组预设。系数生成在控制线程进行；音频线程与工作线程使用同一参数组，旧参数组在两声道处理结束后才能被复用。内部 Q28 处理会降低有效低位精度，不能把启用音效后的输出称作 32-bit 位透明。

PCM 高于 192 kHz 时自动旁路全部音效，屏幕遥测报告直通。该限制用于保留高采样率音频任务的运行余量；要提高音效上限，需要测量包含端口输出、跨线程通信及滤波计算的完整最坏执行时间。空余线程与内存不能证明 768 kHz 下十段均衡可实时运行。交叉馈送为约 700 Hz 低通混合，混合系数总和为 1，避免对同相信号额外放大；未声称实现经过验证的完整 Bauer 模型。

`mqa_core.c` 当前仅保留无处理接口，报告 PCM。项目未集成真正的 MQA 展开、认证或 Renderer；普通滤波器与同步字扫描不能实现这些能力。由播放器解码后的 PCM 可以按其实际传输速率播放，固件不会据此报告 MQA 认证或推断母带采样率。

## 硬件和线程

- tile[0] 运行 USB 收发、端点控制、音频缓冲与 STM32 通信；tile[1] 运行音频端口、右声道均衡和参数控制。
- X1D09 选择两颗晶振，0 选择 49.152 MHz，1 选择 45.1584 MHz，切换后等待 8 ms。
- X0D00 与 X1D11 接入同一 MCLK 网络；tile[0] 的计数端口 X0D11 仅用来读取内部端口计时器，不要求该引脚外接时钟。
- X1D22 输出 BCLK / DSD clock，X1D34 输出 LRCLK / DSD left，X1D13 输出 PCM data / DSD right。
- 固件在改变时钟前通知 STM32 静音 DAC，并保持旧音频时钟约 10 ms 供音量渐降；停止旧位时钟后才切换晶振。该通知没有控制板确认返回，控制线断开或失效时不能保证静音完成；残余冲击需实机试听或测量。

## USB 模式与持久化

| 编号 | 模式 | VID:PID | 状态 |
| --- | --- | --- | --- |
| 0 | UAC2 | 20B1:0016 | Windows 标准驱动已确认枚举及独占 PCM 格式支持 |
| 1 | 山灵设备标识 | 20B1:301F | 实验档位；未验证驱动绑定、私有请求或 ASIO |
| 2 | 飞傲设备标识 | 2972:0093 | 实验档位；未验证驱动绑定、私有请求或 ASIO |
| 3 | UAC1 | 20B1:0017 | 全速类接口配置；未验证游戏主机支持 |

这些标识是现有固件配置，不代表厂商对本设备的支持。原生 DSD 的 USB 数据路径不等同于 Windows 厂商 ASIO 驱动已可用。

USB 描述符不提供序列号，不使用固定字符串冒充芯片唯一编号。Windows 可能按连接端口建立新的设备实例，浏览器重新插拔后也可能需要重新选择设备。

Endpoint0 初始化配置和描述符后，才允许 USB 收发线程进入枚举。模式切换先保存完整配置，成功后断开 USB PHY 500 ms 并重启；保存失败时保留请求并重试，不提前重启。保留 RAM 用于重启时恢复档位。

## 配置管理与保存

XMOS 负责音效、USB 档位和输出配置的主副本、版本协调、自动保存与重试。STM32 保留供电保护、DAC 寄存器执行与回读、音量上限、屏幕按键，以及输出配置备份和累计时间存储。供电保护不等待 XMOS 或网页响应。相关模块为 `settings_manager.c`、`config_store.c`、`controller_link.c` 与 `usb_compat.c`。

启动和重新连接控制板时先读取完整配置及 16 位版本。首次使用时采用 STM32 配置；控制板有更新版本的本地修改时采用该版本，否则将 XMOS 主副本恢复到控制板。每次完整状态回报都重新比较版本，控制板单独复位后也会恢复。版本按 16 位循环计数比较。旧控制板缺少版本协议时继续使用直接控制，由其自行保存输出设置，不接管其配置。

恢复先开启同步静音，发送目标版本，再依次执行音量上限、开机音量、平衡、渐变、自动静音、极性与滤波，最后提交版本。恢复只允许降低当前音量。每个操作等待带编号的完整回读，全部一致后才报告管理就绪；失败约 5 秒后重试。同步期间拒绝网页输出设置，STM32 暂停本地设置修改及日志写入。若连续 5 秒没有成功的同步操作，控制板退出同步静音，按本地保护条件继续工作；状态查询不会延长这个期限。累计时间仍继续计数，写入可能因同步而推迟。

音效和 EQ 写入运行内存后立即生效，停止调整约 2 秒且音频接口连续关闭至少 500 ms 后，XMOS 后台自动保存，不依赖网页轮询。保存失败按 5、10、20、30 秒间隔重试，此后保持 30 秒；保存期间产生的新修改继续排队。暂停播放若仍保持音频接口打开，保存继续等待。USB 档位切换会优先保存完整配置，再重启重新枚举。

配置日志占用 Flash 最后两个扇区；当前 W25Q16JV 为 `0x1FE000～0x1FFFFF`，共 8 KiB。每条占一页 256 字节，包含标记 `ANT3`、递增序号、104 字节完整配置、记录校验及提交标记，写后回读。扇区写满才轮换，擦写失败时保留含最新有效记录的扇区。旧 `ANT2` 音效记录可从最后扇区第一页载入，首次迁移写倒数第二扇区，保留旧副本。STM32 的独立备份不包含 EQ。

启动镜像使用 1 MiB 分区，当前 USB 升级擦写预留为 512 KiB。最后两扇区按配置用途保留，但 SDK 的升级接口尚未统一强制这一边界；扩大固件镜像或调整分区前必须同时调整升级空间，避免覆盖配置。整片擦除或外置编程器覆盖全片会删除配置。最新管理代码的编译通过不代表已完成实机升级、掉电或 Flash 轮换验证。

## USB 控制协议

端点 0 使用 Vendor Device 请求，主机写入为 0x40，读取为 0xC0。多字节数值均为小端；增益单位为 0.01 dB。协议属于 AntDec，没有经过验证的厂商调参协议。

| bRequest | 方向 | 参数 / 返回 |
| --- | --- | --- |
| 0xA0 | 读取 | 最多 28 字节状态 |
| 0xA1 | 写入 | wValue 0～3：选择 USB 档位并重新枚举 |
| 0xA2 | 写入 | wValue 0～5：选择均衡预设 |
| 0xA3 | 写入 | wValue 0/1：设置交叉馈送 |
| 0xA4 | 写入 | wIndex 0～9，8 字节：频率 uint16、增益 int16、Q×100 uint16、滤波类型 uint8、启用 uint8 |
| 0xA5 | 读取 | wIndex 0～9，返回上述 8 字节参数 |
| 0xA6 | 写入 | 恢复自定义频段的默认频率、类型、Q、零增益及前级 |
| 0xA7 | 写入 | 追加保存请求；设置本身已自动排队，空闲后执行 |
| 0xA8 | 写入 | wValue 作为 int16 前级增益 |
| 0xA9 | 读取 | 12 字节音频主时钟实测计数 |
| 0xAA | 读取 | 8 字节数字电平 |
| 0xAB | 读取 | 24 字节 STM32 状态快照与累计播放时间 |
| 0xAC | 写入 | wIndex 为控制板操作号，wValue 为值，见下表 |
| 0xAD | 读取 | 32 字节 AntDec 型号与功能信息 |
| 0xAE | 读取 | 18 字节控制板输出设置与配置版本；允许只读前 16 字节 |

0xA0 返回偏移：0～3 为 `ADO1`；4 USB 档位；5 所选预设；6 交叉馈送；7 格式；8～11 实际传输采样率；12 接口位深；13 的 bit0 为 USB 在线、bit1 为音频接口打开、bit2 为自定义参数已配置；14～15 为前级增益；16～19 保留为 0（未提供可信 MQA 元数据）；20～23 为 XMOS 本次运行播放秒数，重启归零；24 为完整配置保存状态：0 未报告保存、1 排队、2 已保存、3 失败；25 的 bit0 为后台自动保存可用、bit1 为已接管控制板配置、bit2 为后台维护定时器不可用、bit3 为配置恢复失败；26～27 保留。设备累计时间使用 0xAB，不能使用此处的运行计时替代。

0xAB 返回偏移：0～3 `CTL1`；4 的 bit0 在线、bit1 有待处理请求、bit2 配置同步中或未就绪、bit3 同步失败；5 为滤波 bit0～2、DAC 在线 bit3、耳放使能 bit4、用户静音 bit5、就绪 bit6、DAC 静音 bit7；6 为半分贝衰减步数；7 电源阶段；8 供电故障码；9 为控制板存储状态，bit0 写入异常、bit1 支持滤波掉电记忆、bit2 本地设置尚待保存、bit3 支持扩展输出设置、bit4 支持配置版本与同步、bit5 正在同步；10～11 PG1、12～13 PG2、14～15 VDDA（uint16，mV，20 mV 分辨率）；16 请求编号、17 确认编号、18 结果（1 等待、2 成功、3 执行失败、4 超时）、19 操作号；20～23 为 STM32 持久累计秒数。请求只有获得对应编号的完整快照及确认才算完成。旧控制板仅有基础字段，输出设置需同时核对音频板功能位与控制板能力。

0xAD 返回偏移：0～3 `ADC1`；4 协议版本 1；5 型号编号（O1 为 1）；6～7 功能位 uint16，bit0 DAC、bit1 EQ、bit2 电平、bit3 累计计时、bit4 USB 模式、bit5 交叉馈送、bit6 输出设置接口、bit7 XMOS 后台配置管理可用；8～11 PCM 上限 Hz；12～15 EQ 上限 Hz；16 EQ 频段数；17～19 保留；20～31 为零结尾型号名称。O1 正常报告 `0xFF`，后台维护定时器不可用时不置 bit7；输出设置接口存在不代表控制板固件已支持，需要再读 0xAE。

0xAE 返回偏移：0～3 `OUT1`；4 的 bit0 为控制板在线、bit1 支持输出设置版本 1、bit2 管理就绪、bit3 同步失败、bit4 已由 XMOS 管理；5 为参数版本；6～15 依次为滤波、平衡 int8、开机衰减、最小允许衰减、淡入速度、淡出速度、自动静音门限、自动静音时间、极性掩码、自动静音开关；16～17 为配置版本 uint16。衰减与平衡均以 0.5 dB 为单位；正平衡偏右。参数与 0xAB 来自同一完整回传快照。版本不支持或控制板离线时，支持位清零，参数不应被使用。旧客户端可只请求前 16 字节。

0xAC 使用以下操作；4 为固件内部查询，15 为配置同步，两者均不接受主机直接写入。运行音量不写入设备配置，其余输出设置由 XMOS 自动管理、STM32 保存备份，不需要发送 0xA7。

| 操作号 | 设置 | 值 |
| --- | --- | --- |
| 1 | 数字滤波 | 0～7 |
| 2 | 运行主音量 | 0～200 个 0.5 dB 衰减步进，设备限制音量上限 |
| 3 | 用户静音 | 0/1 |
| 5 | 清零播放计时 | 0 |
| 6 | 左右平衡 | int8 的低 8 位，-24～24，单位 0.5 dB |
| 7 | 开机衰减 | 0～200，不能小于最小允许衰减 |
| 8 | 最小允许衰减 | 0～200，限制最大音量并自动调整超限的开机音量 |
| 9 / 10 | 淡入 / 淡出速度 | 芯片速度值 0～255 |
| 11 | 自动静音门限 | 1～255，默认 8 |
| 12 | 自动静音时间 | 1～255，默认 15，实际延时随采样率变化 |
| 13 | 极性掩码 | bit0 左、bit1 右，其余为零 |
| 14 | 普通自动静音 | 0/1，不影响供电与异常时钟保护 |

控制板对每项做范围检查和所需寄存器回读，应用失败时拒绝请求并保持配置未提交。主机收到匹配的执行确认后，仍需通过 0xAE 核对所设置字段。XMOS 主配置保存状态见 0xA0 偏移 24；STM32 本地备份保存状态见 0xAB 偏移 9 的 bit2 / bit0。

0xA9 使用 `bmRequestType=0xC0`、`wValue=0`、`wIndex=0`、`wLength=12`。返回偏移 0～3 为 `CLK1`，4～7 为主时钟计数增量 uint32，8～11 为 100 MHz 参考计时增量 uint32。主机计算 `MCLK_Hz = cycles × 100000000 / reference_ticks`。测量窗口约 500 us，复用 XUA 已配置的端口计时器，仅作读取，不切换晶振或占用新的引脚。窗口超过 1 ms 的结果应重读，避免 16 位音频时钟计数器多次回绕。该值是 XMOS 的 X0D00 输入端所见时钟，不代表排阻、板间连接及 DAC 第32脚上的波形；它也不能判断幅度、占空比或抖动。

滤波类型 0 禁用、1 Peak、2 Low shelf、3 High shelf、4 Low pass、5 High pass。默认 Custom 前级为 0 时，程序按最大正增益自动衰减；多个滤波器叠加仍可能削波，需自行给出足够前级余量。

## 板间脉宽协议

两根独立信号线，空闲为高。起始为低 600 us、高 150 us；每位 1 低 280 us、0 低 120 us，随后高 120 us。高位先发。CRC8 多项式 0x07、初值 0x5A。

XMOS → STM32 使用 X0D37 → PC6，32 位帧：

| 位 | 含义 |
| --- | --- |
| 31:28 | 固定 0xA |
| 27:25 | 格式：0 Idle、1 PCM、2 DoP、3 Native DSD |
| 24:20 | 采样率编码 |
| 19:18 | 位深：0 未知、1 16、2 24、3 32；DSD 界面按 1-bit 解释 |
| 17:16 | USB 档位 |
| 15 | 所选交叉馈送开关 |
| 14:12 | 实际生效预设，高速或 DSD 时为 0 直通 |
| 11 / 10 / 9 / 8 | 静音 / USB 在线 / 音频接口打开 / 自定义均衡实际生效 |
| 7:0 | 对前 3 字节计算的 CRC8 |

采样率编码 1～10 依次为 44.1、48、88.2、96、176.4、192、352.8、384、705.6、768 kHz；11～14 为 DSD64、128、256、512。每帧结束后空闲约 60 ms，再发送下一帧。状态帧与电平帧交替发送，状态更新周期约 140 ms；采样率或格式变化时优先更新状态。

STM32 → XMOS 使用 PC7 → X0D38，24 位：高 4 位 0x5，其后 4 位命令、8 位参数、8 位 CRC8。命令 1 为 USB 档位、2 均衡预设、3 媒体键、4 交叉馈送。媒体参数 1 播放/暂停、2 下一曲、3 上一曲、4 静音。屏幕发出的这些原有命令没有独立确认，应结合回传状态检查。

单根 USB 控制桥使用 XMOS → STM32 的 0xC 帧：操作 4 位、编号 8 位、值 8 位、CRC8，操作号同 0xAC。STM32 回传命令 5 开始快照（参数为编号），6～11 为六个状态字段；命令 14 的前四字节为累计秒数的低到高字节，支持输出设置时继续发送参数版本字节 1 和十字节参数，支持配置同步时再发送两字节配置版本；命令 15 为存储状态字节，最后命令 12 确认或 13 拒绝（参数为相同编号）。XMOS 按能力选择基础、输出设置或带配置版本的完整字段掩码，只有字段齐全且编号匹配当前请求才提交快照。300 ms 自动重发，1.8 s 超时，每秒自动查询，2.5 s 没有完整回复判离线。控制板接收队列为八槽，容纳扩展回传期间到达的遥测与请求；快速静音仍在回传高电平间隙处理。

内部操作 15 的参数高两位为同步步骤：`00` 开始并携带目标版本高四位，`01` 携带低六位，`10` 携带中六位，`11` 提交并核对高四位。开始和提交只使用参数低四位，其余两位保留。复制期间的设置执行不递增本地配置版本，成功提交后采用目标版本；中断超时时若已收到完整版本，则保留该版本，后续离线本地修改继续递增。重发提交可重复执行。

XMOS → STM32 的 0xD 帧含低 20 位本次运行播放秒数与 CRC8，计数变化时替换一个电平帧槽，状态帧保持原节奏。STM32 用增量维护持久累计时间，每 120 秒在两页 Flash 内循环追加，停止播放时补存。两端固件应配套升级。控制板接收队列可保留回传快照期间到达的状态、电平和计时帧。

## 库修正

`lib_xua` 的 HID 描述符补丁允许 UAC2 与 UAC1 同时生成正确的 HID 数据；HID 媒体报告长度为 1 字节。切回 PCM 时清除上一流的 Native DSD 模式。`lib_xud` 增加 `XUD_UserEnumerationReady` 默认空回调，应用覆盖后在首次枚举前等待配置载入完成。

`lib_xud/src/user/client/XUD_EpFunctions.c` 的 SETUP 等待增加三个默认禁用的维护回调：`XUD_UserSetupIdleInterval`、`XUD_UserSetupIdle`、`XUD_UserSetupIdleUnavailable`。应用启用 50 ms 维护周期，在 Endpoint0 同一线程处理菜单命令队列、自动保存及重试，与固件升级串行使用 Flash；USB SETUP 事件优先，DFU 模式禁用维护。等待期间借用一个硬件定时器，返回前释放；分配失败退回原等待路径并报告管理异常，网页可通过普通控制请求触发保存服务。硬件定时器的实际可用性尚未实机验证。更新依赖时必须保留或重新核对这些修改。

## 构建与镜像

Windows 可从仓库根目录运行构建脚本，自动加载 XTC 环境、用 CMake 生成构建目录、编译并生成完整 Flash 镜像与 USB 升级镜像：

```powershell
& './XMOS/tools/build_xmos.bat'
```

需安装 Git、CMake 和 XTC 15.3.1。脚本以自身位置定位工程，不依赖固定盘符或用户名；默认 XTC 路径为 `%ProgramFiles%/XMOS/XTC/15.3.1`，其他安装位置通过 `XMOS_TOOL_PATH` 指定。优先使用 PATH 中的 CMake，找不到时查找当前用户 Cube 安装的 CMake。

`dependencies.json` 固定实际使用的 11 个依赖版本，`tools/prepare_dependencies.ps1` 自动从清单中的官方仓库下载缺少的依赖，并应用 `patches/lib_xua.patch`、`patches/lib_xud.patch`。`modules/` 整体作为本地缓存，不作为子模块上传；项目对第三方库的修改完整保存在补丁中，避免只上传仓库指针而遗漏代码。依赖已就绪时可离线构建，首次准备需要访问 GitHub。脚本保留已有修改，版本不符或补丁冲突时停止，不重置缓存。

修改第三方库后，应同时更新对应补丁。可在仓库根目录使用 PowerShell 重新导出，例如：

```powershell
git -C XMOS/modules/lib_xua diff --binary HEAD --output=../../patches/lib_xua.patch
git -C XMOS/modules/lib_xud diff --binary HEAD --output=../../patches/lib_xud.patch
```

上游更新时同时修改版本清单和补丁；下载的依赖保留各自的 `LICENSE.rst`。仅使用当前工程未依赖的库时，也需先将其加入版本清单。

输出 `bin/app_antdec_o1.xe`。使用 `xflash --factory <xe> --boot-partition-size 0x100000 -o <factory.bin>` 生成量产镜像，使用 `xflash --factory-version 15.3 --upgrade 1 <xe> -o <dfu.bin>` 生成升级镜像。

接入 XTAG 后，用 `xrun <xe>` 临时运行，或 `xflash --boot-partition-size 0x100000 <xe>` 固化烧录。使用后一个命令前应保留需要的已有 Flash 配置，不假定工具一定保留启动分区以外的扇区。没有 XTAG 时可以用外置编程器首次写入完整镜像，之后通过 USB 升级。Windows 已确认标准音频枚举、PCM 独占格式及单根 USB 控制读写，不能据此推断模拟输出质量或原生 DSD/ASIO 验证完成。


## 网页控制与峰值遥测

网页控制台见 [Web 说明](../Web/README.md)。使用现有 WinUSB 控制接口，通过端点 0 设置十段 EQ、前级、音效和交叉馈送，保留音频播放接口。DAC 滤波、音量、静音、整机供电与累计计时均由同一 USB 控制桥提供，无需控制板 USB。

新增厂商读取请求 0xAA，返回 8 字节：MTR1、有效标志 uint8、左声道 uint8、右声道 uint8、测量位置 uint8（1 表示 EQ 后、DAC 音量前）。电平 0 为静音，1～121 表示 -120～0 dBFS。AudioHub 在最高 192 kHz PCM 路径中累计 50 ms 窗口峰值；对数换算在控制线程完成。DSD/DoP 和超过 192 kHz 的 PCM 不计算峰值。

板间电平帧为 32 位：31:28 为 0xB，27:25 保留，24 为有效标志，23:16 为左电平，15:8 为右电平，7:0 为前三字节的 CRC8。该帧不覆盖状态帧的播放格式、位深和采样率；控制板独立检查电平超时。

Windows 升级工具 tools/dfu_upgrade.py 使用系统 WinUSB，仅接受 xflash --upgrade 生成的 *_dfu.bin。先切到标准 UAC2 并关闭占用 USB 控制接口的网页或其他程序，再运行工具。64 字节分块下载并检查 DFU 状态，升级后等待标准音频设备重新枚举。使用外置编程器时仍应写入 *_flash.bin 完整镜像。
