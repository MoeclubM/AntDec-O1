# STM32F105 控制板

STM32F105RCT6，72 MHz，256 KiB Flash，64 KiB RAM。使用 STM32CubeMX 管理 `AntDec-O1.ioc` 与外设生成文件，用 Cube CLI 构建。

## 模块

| 文件 | 职责 |
| --- | --- |
| `Core/Src/board_hw.c` | 逐通道 ADC 读取、VREFINT 供电估算、微秒延时、I2C 总线恢复 |
| `Core/Src/power_seq.c` | 电源状态机、PG 异常保护与输出使能 |
| `Core/Src/es9039q2m.c` | ES9039Q2M 初始化、回读、主音量与左右平衡、极性、音量策略及自动静音 |
| `Core/Src/xmos_link.c` | XMOS 脉宽协议收发、CRC8 校验、链路超时与静态电平回退 |
| `Core/Src/st7789.c` | 屏幕识别、分块绘制与 SPI DMA 发送 |
| `Core/Src/ui.c` | 状态界面与三键交互 |
| `Core/Src/device_store.c` | 累计播放、输出设置掉电记忆与共享 Flash 循环日志 |
| `Core/Src/usb_debug.c` | 可选 USB 虚拟串口诊断与命令控制 |

整机设置由 XMOS 统一管理。STM32 负责独立供电保护、执行和回读 DAC 设置、约束最大音量、屏幕按键，并保留输出设置备份及累计播放时间。XMOS 不在线时仍能依靠本地备份启动和保护，板上滤波修改递增配置版本；重新连接后由 XMOS 比较版本并协调恢复。累计时间仍保存在 STM32，未迁移到 XMOS Flash。

ADC 使用软件触发并逐通道轮询 PA0、PA1、内部 VREFINT。PG 值是 ES9312 状态脚电压；VDDA 根据典型 1.2 V 内部基准估算，不是经过外部仪器校准的精密测量。SPI1 使用 DMA；当前应用没有使用 ADC DMA 循环采集。

屏幕驱动按读回编号选择 ST7735 160×128 或 ST7789 320×240 横向画布；读回不可用时默认 ST7789。方向沿用当前设置。

## DAC 配置

- I2C1 使用 PB6 / PB7，100 kHz，探测地址 0x48～0x4B；芯片编号必须为 0x63。底板两个地址脚均接地，预期地址是 0x48。
- 寄存器 0 写入 0x02，启用模拟部分。由自动采样率检测在需要时进入 64FS；不对所有采样率强制 64FS。
- 寄存器 1 使用同步模式 0xF7；寄存器 3 为自动速率检测、寄存器 5 为自动时钟档位。当前硬件的音频信号来自同一晶振，菜单不提供缺少配套时钟配置的异步模式。
- 寄存器 34 保持校准电阻启用；41 关闭 GPIO 输出、42 关闭数字输入，保护 GPIO8 与 ES9312 的校准连接。
- 初始化全程静音，回读系统配置、模式与静音寄存器后才允许上电流程继续。
- 默认开机音量为 -20 dB，步进单位为 0.5 dB。界面每次调整两个步进，即 1 dB；各入口均受设备最大音量限制。

滤波器对应 ES9039Q2M 手册寄存器 88：

滤波在写入并回读成功后自动安排本地备份，板上按键、XMOS 控制桥和控制板诊断接口均使用同一保存路径。连续 2 秒未修改才追加记录；重复选择同一项不写入。上电读取本地滤波，在 DAC 静音初始化阶段写入并回读，不依赖上位机或 XMOS 在线；新版 XMOS 随后根据配置版本恢复主副本或采纳更新的本地修改。

| 编号 | 滤波器 |
| --- | --- |
| F0 | Minimum phase |
| F1 | Linear phase fast roll-off apodizing |
| F2 | Linear phase fast roll-off |
| F3 | Linear phase fast roll-off low ripple |
| F4 | Linear phase slow roll-off |
| F5 | Minimum phase fast roll-off |
| F6 | Minimum phase slow roll-off |
| F7 | Minimum phase slow roll-off low dispersion |

输出设置为固定 10 字节版本 1：滤波 uint8、平衡 int8、开机衰减、最小允许衰减、淡入速度、淡出速度、自动静音门限、自动静音时间、极性掩码、自动静音开关。两个音量值与平衡均以 0.5 dB 为单位；平衡范围 -24～24，正值衰减左声道、负值衰减右声道。开机衰减不得小于最小允许衰减，主音量范围 0～200 步。降低最大音量时立即限制当前音量，并同步限制开机音量；运行主音量本身不写入该配置，冷启动恢复开机音量。

寄存器 74/75 分别写入主衰减加平衡补偿，寄存器 87 的低两位控制左右极性。极性改变前使用快速静音并等待 2 ms，写入回读成功后恢复原来的用户静音状态。正常音量渐变使用寄存器 82/83，默认 2/32；网页慢、标准、快对应淡入 1/2/8、淡出 8/32/128。采样率切换和供电故障临时把下降速度置为 255，解除静音时恢复用户速度；寄存器 84 的异常时钟快速下降保持 255。

自动静音由寄存器 123 控制，保留其高六位默认值。门限寄存器 126～127 默认 8，网页低、标准、高对应 1/8/32；恢复门限为进入门限加 `max(2, level/4)`，默认仍为 10。时间寄存器 124～125 默认 15，网页短、标准、长对应 55/15/5；时长按手册 `2^18 / (time × FS)` 变化。寄存器 125 的输出共模接地位始终保持关闭，寄存器 130 软启动设置不向用户开放。

## 操作与显示

左键 PC13 减小音量，右键 PC14 增大音量，长按连续调整。中键 PB1 在 XMOS 链路在线时发送播放/暂停媒体键；离线时切换 DAC 本地静音，避免一次按键同时改变主机播放与本地静音后出现相反状态。

长按中键 550 ms 进入设置，左右选择类别，短按中键打开选项子菜单。左右浏览候选值，短按中键确认后才应用；长按中键或选择“返回”取消当前编辑。设置包括 DAC 数字滤波、均衡预设、交叉馈送、USB 档位；8 秒无操作取消未确认的更改并退出。设置进入时同步音频板遥测中的档位与开关，切换 USB 前显示断开提示。

主界面显示播放格式、采样率、接口位深、音量、数字滤波、纵向左右声道电平和累计播放时间。正常时只显示一个“正常”状态；上电阶段显示“启动中”，供电、解码、通信、耳放或存储异常时显示对应文字，多个异常每 2 秒轮换。PG1/PG2、VDDA 和芯片编号保留在诊断接口中。

XMOS 提供当前运行的播放秒数，STM32 根据秒数增量维护设备累计时间，源计数重启时建立新基准。音频接口打开时递增，包括静音数据；它不表示曲目进度。累计时间每 120 秒保存，停止播放时补存，突然断电最多丢失最近约两分钟。设置中的“累计时间”子菜单选择“确认清零”可立即清零并保存，网页也提供确认后清零。

计时与全部输出设置共用 Flash 最后两页 `0x0803F000～0x0803FFFF`，每页 2 KiB，新记录为 32 字节：序号、秒数、秒数反码、10 字节输出设置、2 字节配置版本、CRC32 和最后写入的提交标记 `0x41445331`。CRC32 使用反射多项式 `0xEDB88320`，覆盖前 24 字节，初值和最终异或均为 `0xFFFFFFFF`。旧版 32 字节记录的保留零自然成为版本 0。启动扫描同时读取原来的 16 字节计时/滤波记录，迁移时保留累计时间和已存滤波，其余字段使用默认值。

一页写满才切换、擦除下一页，擦除或编程失败时保留含最新有效记录的页面。启动检查提交标志、CRC、秒数反码与设置范围，中途掉电的未提交条目不会替代旧记录。写入后回读确认，只有成功才清除设置待保存状态。设置连续 2 秒未修改才合并写入；合并等待期间的停止播放补存也会保留。

本地设置实际改变时递增 16 位配置版本。XMOS 使用内部操作 15 开始、传输目标版本并提交配置同步；同步时立即快速静音，普通静音判定持续保持这一条件，复制设置不递增版本。先恢复音量上限等输出参数，提交后采用目标版本并恢复原保护条件下的声音，不改变用户静音选择。同步期间暂停日志保存、计时清零和本地菜单修改，累计时间继续计数。连续 5 秒没有成功同步操作则退出，普通查询不刷新超时；已收到完整版本时保留该版本，以便后续本地修改能够正确递增。未完成的配置由 XMOS 重连后重新核对。

附加链接断言阻止应用镜像占用这 4 KiB，不修改 Cube 生成的外设与 HAL。普通局部固件下载可保留日志，整片擦除会清除计时与输出设置。保存失败显示存储异常并每 5 秒重试；循环日志服务不依赖 XMOS 在线。

USB 在线状态来自 XMOS 遥测，播放标志不等同于检测到可听声音；文件本身的原始位深也无法从 USB 传输位深推断。

链路超过 300 ms 无有效帧会清除旧采样率、位深与播放状态，随后使用引脚静态电平判别子板状态。屏幕分段刷新期间继续轮询供电保护。完整协议见 [XMOS 说明](../XMOS/README.md)。

## 构建与下载

在仓库根目录执行：

```powershell
Set-Location STM32/AntDec-O1
$env:PATH = 'C:/Program Files (x86)/Arm GNU Toolchain arm-none-eabi/14.3 rel1/bin;' + $env:PATH
& "$HOME/.local/stm32cube/bin/cube.exe" cmake --preset Release
& "$HOME/.local/stm32cube/bin/cube.exe" cmake --build --preset Release
```

产物为 `build/Release/AntDec-O1.elf`、`.hex`、`.bin`。使用 J-Link Commander，设备 STM32F105RC、SWD、4000 kHz，执行 `loadfile` 指向 `.hex`，随后复位运行。

调整外设必须通过 Cube 修改并重新生成，禁止手工修改 HAL、驱动配置及外设生成文件。当前输出状态无法证明模拟供电幅值、耳放冲击声及输出质量，需要在底板接入后测量。

## USB 日志诊断

USB 虚拟串口由 Cube 的 USB_DEVICE CDC_FS 配置生成，使用控制板 USB-B 的 PA11/PA12 数据线。接电脑后预期枚举为 AntDec_O1_Debug（0483:5740）。串口可设置 115200、8N1；USB 本身不依赖该波特率。打开串口并置 DTR 后每秒输出一份状态。

命令以回车结束：`status` 立即读取状态；`stream off` 停止周期输出；`stream on` 恢复；`help` 显示说明。日志输出电源状态、PG 指示电压、使能脚电平、DAC 编号和初始化步骤、失败寄存器及期望/实读值、I2C 错误和总线电平，以及 XMOS 链路、帧数和播放数据。

I2C 错误 0x04 为无应答，0x20 为超时。初始化步骤 1 为读编号、2 为写配置、3 为回读、4 为完成。诊断数据包含总线错误、芯片编号和配置回读失败寄存器。这些状态不能单独证明主时钟缺失；STM32 网表没有连接可直接测量 DAC MCLK 的输入脚。

USB 日志只提供运行状态和命令，不提供断点或寄存器级调试。旧固件需要先更新一次，之后读取日志无需保持 SWD 连接。调试器是否会倒灌取决于接线和电源设计，不能由固件消除；J502 的 1 脚直接连接系统 3.3 V，不应将调试器供电输出接入已供电的电源轨。VTref 应按调试器说明仅作电压参考。

按当前控制板网表，USB1 的 VBUS 引脚未接入 `STM_USB_VBUS` 网络，VBUS 检测保持关闭；控制板仍需由底板供电。USB 日志的实际枚举与收发必须在插入控制板 USB 数据线后确认。


## 网页控制与电平

网页控制台见 [Web 说明](../Web/README.md)，日常控制全部通过 XMOS USB。XMOS 发送带编号与 CRC8 的板间请求，STM32 回传完整状态、输出参数、配置版本及执行确认；支持滤波、音量和本地静音，数字滤波写入寄存器 88 后回读确认。存储状态 bit4 表示支持配置版本同步，bit5 表示正在同步。新管理协议需要两端配套更新；当前源码已编译，管理恢复和同步保护尚未实机验证。控制板 USB 的 api 串口命令继续作为可选诊断功能，请求带编号并返回 JSON。

主屏不显示芯片 ID。左右声道电平来自 XMOS 的 PCM 峰值，显示位置为 EQ 后、DAC 音量衰减前，与网页一致。纵向刻度为 0～−90 dBFS，电平快升、按约 24 dB/秒回落，独立峰值标记保持 1 秒后按约 12 dB/秒回落。显示不随本地音量降低而贴底；−9 dB 以上为黄色、−3 dB 以上为红色。

最高 192 kHz PCM 有效，DSD 和更高采样率显示不可用。板间电平帧与状态帧交替发送，时间变化时占用一个电平帧槽；电平超过 400 ms 未更新会失效。停止播放或测量失效时清除平滑和峰值状态。按键和供电保护在屏幕分块绘制期间继续处理。

采样率切换前，控制板接收 XMOS 的 1.35 ms 快速静音脉冲，经 I2C 静音 DAC，至少保持 48 ms，并等待音频板退出硬件静音。短暂时钟切换期间维持耳放开启。DAC 自动静音不再将输出共模拉到地；仍需实机试听或仪器确认残余冲击。

新版硬件的 PA9 未接 USB VBUS，控制界面不再依赖该脚电平。USB 使用 Cube 生成的关闭 VBUS 检测配置。所有外设生成文件与 HAL 的变更仍须通过 Cube 完成。

当前 STM32 固件下载使用 J-Link。F105 的系统自带 USB 下载程序需要在检测阶段看到 PA9 为高，当前接线不能直接依赖这一方式；尚未实现自定义 USB 下载程序。应用中的 USB 日志功能与系统下载程序的检测条件不同，参见 [ST AN2606](https://www.st.com/resource/en/application_note/an2606-stm32microcontroller-system-memory-boot-mode-stmicroelectronics.pdf)。

字体使用工具 tools/generate_fonts.py 从 ui.c 字符集合生成 12/16/24 像素字库，依赖 Pillow 和微软雅黑；可用 --font 指定同样覆盖中文的字体。
